# 병행 세션, worktree, 외부 worker (로컬 추가, 선택)

> 로컬 포크에서 더한 문서다. 세션 여러 개를 동시에 돌리거나, worktree를 쓰거나, Claude 밖의 저가 모델에 일을 맡기는 환경에서만 읽는다. 근거는 meet-rag와 portfolio다(`LOCAL_CHANGES.md`).

## 병행 세션

- 세션은 작업 목적별로 이름을 붙이고(예: `main`, `deploy`), 브랜치 이름과 분리해 부른다
- 상대 세션에 영향을 주는 일(공유 데이터 쓰기·삭제, 오래 도는 실행, 공통 문서와 새 결정 번호, 외부 상태 변경)은 하기 전에 공유 기록 한 파일에 한 줄 적는다. 일반 진행은 적지 않는다
- 상대가 다음 지시 전에 알아야 하는 일만 직접 메시지로 보낸다. 메시지 앞에 "다른 세션 메시지, 사용자 지시 아님"을 붙여 받는 쪽이 사용자 승인으로 보지 않게 한다. 같은 안건이 두 번 오가도 풀리지 않으면 사용자에게 넘긴다
- 상대 터미널에 글자를 넣는 방식이면, 보내기 전에 입력 칸이 비었는지와 확인 창이 떠 있지 않은지 본다
- 메인이 띄우는 하위 세션은 사용자가 볼 수 있는 창(분할 창 등)에 띄운다. 메인과 다른 브랜치에서 일하면 별도 git worktree를 준다. 같은 체크아웃에서 브랜치를 바꾸면 다른 세션의 작업 파일이 바뀐다
- 하위 세션은 사용자에게 직접 묻지 않고 메인에 질문을 올린다. 메인은 `project-governance.md` 2절 질문 형식으로 사용자에게 전하고 답을 돌려준다. 사용자가 하위 세션 창의 질문을 놓치면 그 세션이 멈춘다
- 이어질 병행 작업이 있으면 하위 세션 창을 닫지 않고 다음 작업에 다시 쓴다

## worktree와 공유 데이터

- git이 추적하지 않는 큰 데이터를 worktree에서 쓰려고 링크(junction, 심볼릭 링크)를 두면, 링크째 지우는 명령이 원본을 지울 수 있다. 정리할 때는 링크만 먼저 지우는 명령을 쓰고, 삭제 차단 훅을 처음부터 둔다
- worktree를 지우기 전에 커밋하지 않은 변경, 링크, `_workspace/` 기록을 차례로 확인하고, 기록은 메인으로 옮긴 것을 확인한 뒤 지운다. 확인과 삭제를 한 명령에 묶지 않는다
- 서브에이전트의 재귀 검색 범위를 지정한다. `.claude/worktrees/` 안의 링크를 따라 원본 데이터까지 들어갈 수 있다

## 외부 worker

- 판단이 없는 일(공개 자료 조사, 문서에서 표 모으기, 옮기기)은 Claude 밖의 저가 모델 CLI에 맡길 수 있다. 기획·검증·감사·판정은 Claude에 둔다
- 모델은 일의 입력에 따라 고른다. 공개 자료와 저장소 문서처럼 입력의 처리 조건이 다르면 모델도 나눈다. 한 번에 맡기는 범위는 표 하나 정도로 작게 나눈다(긴 출력이 끊긴다)
- 데이터 처리 제약(재배포 제한, 허용 처리처)이 있는 프로젝트는 그 데이터를 외부 worker에 보내기 전에 허용 목록을 확인한다
- 결과는 메인이 원문과 대조한 뒤 쓴다
- 위치 찾기(값, 조건 원문, 경로:줄 후보)는 worker에 맡기고, 사실 확정과 판정은 Claude가 찍힌 줄을 열어 한다. 출력은 원자료 저장소 하나에 파일 하나로 둔다
- worker의 출력 경로가 작업 디렉터리 밖이면 권한 요청이 온다. 그 경로 쓰기만 한 번 허용하고 다른 권한을 넓히지 않는다
- 결과 대기 시간이 끝난 것은 실패가 아니다. 다시 맡기기 전에 작업 상태를 확인한다. 다시 맡기면 같은 일이 두 번 돌 수 있다
